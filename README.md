# 見下ろし視点 2D キャラクター歩行デモ

8列 x 4行 (下 / 上 / 右 / 左) のスプライトシートで、キャラクターが 4方向に歩ける
最小構成のデモです。HTML5 Canvas と素の JavaScript だけで動き、ビルド手順はありません。

## 動かす

`index.html` をブラウザで直接開くだけで動きます。

ローカルサーバ経由で開きたい場合:

```sh
python3 -m http.server 8000
# http://localhost:8000/ を開く
```

### 操作

| キー | 動作 |
| --- | --- |
| 矢印キー / WASD | 移動 (斜め移動あり) |
| F1 | デバッグ表示 (fps / 座標 / 当たり判定) |

## 素材について

`assets/character.png` は、リポジトリ内の `chara.png` (行見出し・列見出し・罫線が
入った元画像) から次のコマンドで生成しています。

```sh
pip install pillow
python3 tools/slice_reference_sheet.py chara.png -o assets/character.png \
    --frame-height 64 --mirror-row 3=2
# → 344x256 / 1コマ 43x64
```

`chara.png` を描き直したら、同じコマンドを実行すれば `assets/character.png` を
更新できます。

### 切り出しスクリプトの挙動

- 罫線 (画像を横断する暗い線) を検出してマスの位置を求めます。
- 背景は外周から届く範囲だけを塗りつぶし式に消すため、輪郭線で囲まれた
  ドレスの内側などは残ります。消えすぎた場合は警告を出すので
  `--tolerance` を下げてください (既定 12)。
- マスごとに個別で切り詰めるとコマ間でキャラの位置がずれてアニメがガタつくため、
  **全コマ共通の矩形**で切り詰めています。
- `--frame-height` で縮小できます。元画像は 1コマ 94x140 と大きく、そのままだと
  32pxタイルの画面に対して大きすぎるため 64px に縮小しています。
  縮小はアルファ乗算してから行うので、輪郭に黒いふちが出ません。
- 罫線の自動検出に失敗したら、マスの位置を直接指定できます:

  ```sh
  python3 tools/slice_reference_sheet.py chara.png \
      --x0 45 --y0 30 --cell-w 117 --cell-h 133
  ```

### 元画像の向きの不揃いについて

**「下」の行以外は、8コマの中に向きの違うコマが混ざっています。**
そのまま8コマ回すと、歩くたびにキャラが「きょろきょろ」します。

各コマの目の位置を測って調べた結果は次のとおりです
(体の中心を 0 とした目の左右位置。プラスが右向き)。

| 行 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 下 | 正面 | 正面 | 正面 | 正面 | 正面 | 正面 | 正面 | 正面 |
| 上 | 正面 | 正面 | 正面 | 正面 | 背面 | 背面 | 背面 | 背面 |
| 右 | 左 | 左 | 左 | **右** | 左 | **右** | **右** | **右** |
| 左 | 左 | 左 | 右 | 右 | 左 | 右 | 右 | 右 |

素材側を描き直すのが本筋ですが、現状の素材でも自然に歩けるよう次の対応をしています。

**1. 向きが揃っているコマだけを使う** (`src/config.js`)

```js
frameSequence: {
  up:    [4, 5, 6, 7],   // 背面向きの4コマ
  right: [3, 5, 6, 7],   // 右を向いている4コマ
  left:  [3, 5, 6, 7],
},
```

**2.「左」の行は「右」の行の左右反転で作る**

「左」の行は左を向いているコマが3つしかなく、しかも脚の動きがほとんど同じで
歩いて見えません。そこでシート生成時に「右」の行を反転して「左」の行に使っています
(`--mirror-row 3=2`)。左右で同じ動きになるので、向きを変えても違和感がありません。

反転は**元画像のマス単位**で行っています。キャラは元画像のマス内でほぼ中央に
立っているため、マスの中心を軸にすれば体の中心線がずれません
(切り詰めたあとの矩形を軸にすると、後ろに流れる髪の分だけ中心が 5〜7px ずれます)。

素材を全コマ向きの揃ったものに描き直したら、`frameSequence` の該当行を消し、
`--mirror-row` を外せば8コマで再生されます。

## 設定

1コマのサイズは画像サイズから自動計算する (`幅 / 8`, `高さ / 4`) ので、
素材の解像度が変わってもコードを直す必要はありません。
挙動を変えたいときは `src/config.js` だけ触れば済みます。

```js
rowOf: { down: 0, up: 1, right: 2, left: 3 },  // 行の並び
frameSequence: { up: [4, 5, 6, 7] },           // 向きごとに使うコマ (省略時は全8コマ)
idleIndex: 0,     // 立ち止まったときに表示する、シーケンス内の位置
walkFps: 10,      // 歩行アニメの速さ
speed: 90,        // 移動速度 (px/秒)
```

立ち絵が不自然なときは `idleIndex` を調整してください
(1コマ目が直立ポーズでない素材もあります)。

## 実装メモ

- **足元基準の座標**: プレイヤーの `x, y` は足元の中心。見下ろし視点では
  当たり判定と重なり順を素直に扱えます。
- **当たり判定は足元だけ**: 見た目の矩形全体ではなく足元の小さな矩形で判定します
  (頭が木に重なっても通れる、という見下ろし視点の定番の挙動)。
- **軸ごとの移動**: X と Y を別々に判定するので、壁に斜めからぶつかっても
  止まらず壁沿いに滑ります。
- **斜め移動の正規化**: 斜めでも速度が 1.41 倍にならないようにしています。
- **斜めのときの向き**: 後から押したキーの軸を向きます。
- **ドット絵の描画**: `imageSmoothingEnabled = false` と整数倍スケール、
  カメラ座標の丸めで、拡大してもぼやけ・ちらつきが出ないようにしています。

## 動作確認

Chromium (Playwright) で以下を確認済みです。

- 4方向の移動と向きの切り替え
- 歩行アニメの循環と、停止時に `idleIndex` の位置へ戻ること
  - 下: `1 2 3 4 5 6 7 0 …` (全8コマ)、停止時は 0
  - 上: `5 6 7 4 …` (背面向きの4コマ)、停止時は 4
  - 右 / 左: `5 6 7 3 …` (向きの揃った4コマ)、停止時は 3
- 使用コマの向きが揃っていること (目の左右位置が 右 +8.3〜+8.8 / 左 -8.3〜-8.8)
- 左右反転による足元のズレが 1px 以内であること
- 歩行中に向きを変えても、コマ番号がシーケンスの範囲外にならないこと
- 斜め移動の速度が正規化されている (0.3秒で約 28px ≒ 90px/秒)
- 壁に向かって歩くと壁の手前で止まる
